## Context

Lot 2 of `spec/lot-2.md` starts on top of lot 1's code. The node and the Worker will exchange requests and responses over `/node/*`; their shapes are defined once in JSON Schema and generated for both languages, like lot 1's contracts. The log catalogue grows with the events of lot 2. Spec: sections 4 and 12.

## Decided spec

- The seven schemas of section 4.1 and `contracts/error.schema.json` (section 4.2), with `additionalProperties: false` on every object; `node-result-request` refers to `transcript-result.schema.json` with a `$ref`.
- `scripts/contracts.sh` (and `--check`) generates them as lot 1 does, and resolves the `$ref` to the generated transcript-result type in both languages, without duplicating it.
- The enum of `event` in `contracts/log-event.schema.json` gains every event of section 12; both loggers accept them.

## Acceptance criteria

- Tests in both languages: a valid instance of each new schema is accepted; an extra field, a `max_jobs` of 0 or 11, an unknown `outcome`, a result whose `transcript` breaks the transcript-result schema, and a heartbeat without `version`, are rejected.
- A test shows that the generated result-request type uses the generated transcript-result type (no second definition).
- A logger test in each language accepts a lot 2 event (for example `job.claimed`) and still rejects an event outside the catalogue.
- `./scripts/contracts.sh --check` passes, and still fails on a stale file.
- `./scripts/check.sh all` passes (`e2e` is skipped until its script exists).
