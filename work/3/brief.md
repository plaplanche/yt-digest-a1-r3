## Context

Section 4 of `spec/lot-1.md`: the transcript result and the log events are defined once in JSON Schema and generated for both languages, and a check fails when the generated files are stale. The loggers of both languages accept only catalogued events.

## Decided spec

- `contracts/transcript-result.schema.json` and `contracts/log-event.schema.json`, exactly as sections 4.1 and 4.2.
- `scripts/contracts.sh` and `--check`, section 4.3; the `contracts` check runs it.
- Generated TypeScript types in `worker/src/contracts/`, Pydantic v2 models in `node/src/yt_digest_node/contracts/`, the catalogue as a TS union and a Python `StrEnum`.
- Loggers of section 4.4: `yt_digest_node.log.emit` and `worker/src/log.ts`.

## Acceptance criteria

- Tests in both languages: a valid transcript result and log line are accepted; a result with an extra field, a bad `video_id` or a bad `status`, and a log line with an unknown event, are rejected.
- `./scripts/contracts.sh --check` fails and names the file when a generated file is edited by hand or a schema changes without regeneration (shown by a test).
- A logger test shows that an event outside the catalogue raises in Python and throws in TypeScript.
- `./scripts/check.sh all` passes.
