## Decided spec

- `POST /mcp` (11.1): Streamable HTTP, protocol `2025-06-18` (the `protocolVersion` of the `initialize` result), `initialize`, notifications answered 202, `ping`, `tools/list`, `tools/call`; the 401 `invalid_token` with `WWW-Authenticate` and `resource_metadata` for every request without a valid access token (10.6).
- The Origin check of 11.2, before authentication.
- The tool `list_subscriptions` (11.3).
- The log events `auth.origin.rejected` and `mcp.tool.call`, and `auth.bearer.rejected` with `surface` `mcp` (section 12).

## Acceptance criteria

- Worker tests: no token, an expired access token, a node token, the operator token and a token of a user whose invite was revoked get 401 with `WWW-Authenticate` on `/mcp`; an access token gets 401 on `/node/*`; a foreign `Origin` gets 403 `origin_rejected` before authentication, and an allowed or absent one passes; `initialize` answers `protocolVersion` `2025-06-18`; `notifications/initialized` gets 202 without a body; `tools/list` returns exactly `list_subscriptions`; `tools/call` returns `{"subscriptions":[]}` with `isError` false.
- E2E tests: E2E-27, E2E-33 and E2E-37 of section 13 (`api` project), and E2E-28 (`browser` project), which runs in CI; where Chromium cannot be installed, `./scripts/check.sh e2e` skips it (section 3.1).
