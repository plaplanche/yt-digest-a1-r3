- `POST /ops/invites`, `POST /ops/invites/revoke`, `GET /ops/users` (section 7), on the tables `invites` and `users` of 6.3.

## Acceptance criteria

- E2E tests (`api` project) against the mocks server: the discovery document; `/google/authorize` refuses a wrong `client_id` or a missing `openid` scope with 400, shows the sign-in form repeating every parameter, and with `login_hint` redirects with a `code` and the `state`; the code gives an ID token whose signature verifies with the JWKS key and whose claims (`iss`, `aud`, `sub` by the subject rule, `email` lowercased, `email_verified`, `iat`, `exp`, `nonce`) follow 5.3; the code is single use; a wrong client secret gives 401 `invalid_client`; userinfo answers for its access token only.
- Worker tests: an invite is stored lowercased; inviting again re-activates a revoked invite; revoking an unknown invite gives 404 `not_found`; `GET /ops/users` lists users sorted by e-mail.
